# 时间与定时器：`base/time` `base/timer`

`TimeUtil`（纯函数的日期计算与格式化）、`Now`（帧缓存时钟、可模拟的逻辑时间）、`TimerWheel`（分层时间轮）。
都不依赖网络与线程库，也不依赖日志：`breeze_time` 用到 `localtime_r`（POSIX，不限 Linux），`breeze_timer` 只依赖标准库。

本文记录**为什么是这个样子**：前身来自 `cpp-game-server-main`（`now` / `time_util` / `timer`）与 `cpp-wind-server`（`Time.{h,cpp}`），
合并时做了哪些取舍、修了哪些 bug。API 的细节与约束写在头文件注释里，本文不重复。

**状态**：debug / release / asan+ubsan 下全部测试通过；`TimerWheel` 另外与一个"一眼看得出对不对"的参考实现做了随机对照（§3.3），
对关键判断逐个改坏做过变异验证（§5）。
**tsan 没有在本机跑过**（环境原因，见 `网络库设计.md` §11.2）。`TimerWheel` 本身是单线程的，没有并发；`Now` 的状态全是原子量，`now_test` 里有"一个线程不停改、几个线程读"的用例，
但这类用例在 tsan 下才真正有说服力，上真机前不要当作已验证。

## 1. 来源与取舍

| 组件 | 来源 | 取舍 |
|---|---|---|
| `TimeUtil` | game-server-main 的 `time_util`（时区作参数的纯函数）+ wind-server 的 `Time.cpp`（`reset_hour`、`reset_weekday`、`Parse`、ISO 8601） | 合并：时区仍是显式参数；**游戏日的刷新时刻（`reset_sec`）与一周从星期几开始（`Weekday`）并进所有日 / 周 / 月函数**；日历换算改用 civil-days 公式（§2） |
| `Now` | game-server-main 的 `now`（帧缓存）+ wind-server 的 `Time.cpp`（原子量、冻结） | 帧缓存的接口保留，内部全换成原子量；GM 偏移 + 冻结；`Str()` 按值返回（§2） |
| `TimerWheel` | game-server-main 的 `timer`（4×256 分层轮，`FlatHashMap<id, Entry*>` + `unique_ptr<Entry>`） | **重新设计**：侵入式双向链表 + slab 节点 + 带代数的句柄，真正 O(1) 取消并立刻释放；空转跳过；`Reset` / `NextDeadlineMs` / 重复定时器的两种补偿策略（§3） |

## 2. `TimeUtil` 与 `Now`

### 在原代码里发现并处理的问题

- **负数的整数除法**（game-server `TimeUtil::DayBegin` 等）：`(ts + tz) / 86400` 对负数向零取整，差一天。时间戳在 1970 年之前、或者时区把本地时间推到 1970 年之前（UTC-5 的 `ts < 5h`）就会错。wind-server 的 `GetLogicalDay` 干脆对负时间戳返回 0。现在统一用向负无穷取整的 `FloorDiv` / `FloorMod`（`time_util_test` `TestNegativeTimestamps`，随机用例覆盖 1811–2604 年与 ±12/14 小时的时区）。
- **日历换算依赖 libc**（`IsSameMonth` 用 `gmtime_r`、`Format` 用 `localtime_r`）：`localtime_r` 取全局的时区锁，且 `Format` 的"本地"是进程时区而不是业务时区。现在用 Howard Hinnant 的 civil-days 公式（整数运算、`constexpr`），与 libc 的 `gmtime_r` / `timegm` 对照过 30 万个随机时间戳（`TestAgainstLibc`），并逐日往返验证了 ±80 万天（`TestCivilRoundTripEveryDay`）。
- **`LocalTimezoneOffset()` 只取"现在"**：夏令时下，对别的时刻是错的。现在接受时间戳参数（`TestLocalTimezoneOffset` 用 POSIX 的 `TZ` 字符串 `EST5EDT,M3.2.0,M11.1.0`，不依赖系统装了 tzdata，并检查了夏令时切换的前后一秒）。
- **`Now` 的静态状态不是原子的**（game-server）：主循环写、别的线程读（比如日志线程取时间）是数据竞争；`Str()` 返回指向共享缓冲区的指针，读的时候可能正被改写。现在状态全是原子量，`Str()` 按值返回一个 20 字节的 `TimeString`（`now_test` `TestConcurrentReadersAndWriter`）。
- **`Now::Ms()` 在第一次 `Update()` 之前返回 0**：任何基于它的逻辑都会错到 1970 年。现在退化成 `LiveMs()`（`TestBeforeFirstUpdateFallsBackToLive`）。
- **GM 偏移要等下一次 `Update()` 才生效**：现在改完立刻刷新缓存。
- 冻结值 `0`（以及 `INT64_MIN`）是合法值：内部用一个哨兵表示"未冻结"，`FreezeMs(INT64_MIN)` 取最接近的值，不会悄悄变成"没冻结"（`TestFreeze`）。偏移加法饱和，不回绕。

### 取舍

- **游戏日**：很多玩法每天凌晨 5 点而不是 0 点刷新。所有日 / 周 / 月函数都带 `reset_sec`（本地时间的秒数，默认 0）：凌晨 3 点属于前一个游戏日，周一 03:00 在 5 点刷新的服里仍属上周，每月 1 号 03:00 仍属上个月（`TestResetHour`；已知答案由独立的 Python `datetime` 实现算出，54 组，`TestDayWeekMonthKnownAnswers`）。
- **时区是固定偏移**：`TimeUtil` 的函数都不读 `TZ`。夏令时由调用方按那个时刻取偏移，或者像大多数游戏服那样在配置里写死一个区域偏移。`Now` 的业务时区同理，**不自动跟踪夏令时**（`SetTimezoneOffsetSec` 显式设置；`ResetTimezoneToLocal` 重新采样本机）。
- **逻辑时间 = 墙钟 + 偏移 / 冻结**，只影响"日历意义"的时间；`SteadyMs()` 不受影响。**定时器、超时、耗时统计一律用 `SteadyMs()`**：GM 把时间拨一年，不能让一堆定时器同时到期。
- 前提：时间戳的绝对值远小于 2^62（别拿 `INT64_MAX` 当"永不过期"传进 `TimeUtil`）。

## 3. `TimerWheel`

### 3.1 在原代码里发现并处理的问题

- **取消的定时器留在轮里直到原本的到期时间**：`CancelTimer` 只是置 `cancelled` 标记并从 `entries_` 里删掉，条目（连同 `std::function` 与它捕获的资源）要等槽被轮到才释放。连接空闲超时这类"每个包都取消再重加"的用法，内存与 CPU 随"取消速率 × 延迟"线性增长（30 秒超时、每秒 10 万次重置就是 300 万个死条目）。现在取消立刻从链表摘下并释放回调（`TestNoNodeLeak`：20 万次添加 + 取消后节点数仍是 1；`TestCancelReleasesCallbackImmediately`：用 `shared_ptr` 引用计数证明捕获物立刻被释放）；还加了 `Reset`（不动回调、不重新分配，`TestReset` 里 2 万次重置节点数不变）。
- **回调抛异常会留下悬空指针**：`fire_list` 是局部变量，抛出时里面的 `unique_ptr<Entry>` 随栈展开销毁，而 `entries_` 里还存着它们的裸指针，之后 `CancelTimer(id)` 就是 use-after-free；同一 tick 里没触发的定时器也随之丢失。现在每个定时器触发前已经从槽里摘下，用 RAII 收尾，抛出时本 tick 剩下的留到下一次 `Advance` 继续触发（`TestCallbackThrows`）。
- **`Tick` 逐 tick 追赶**：`while (cur_tick_ < target_tick) ++cur_tick_`，停顿 30 天（tick = 1ms）就是 26 亿次空转。现在用每层 256 位的占用位图直接跳到下一个有事件的 tick（`TestFastForward`：推进 30 年 < 1 秒）。
- **`Tick` 不可重入**：回调里再调 `Tick` 会递归处理同一批槽。现在回调里的 `Advance` 被忽略（`TestAdvanceIsNotReentrant`）。
- **重复定时器的补偿策略是写死的**：长停顿后会连续补触发，回调慢的时候会雪崩。现在默认丢掉错过的周期并保持相位（`kSkipMissed`），可选逐个补（`kCatchUp`）（`TestRepeatPolicies`）。
- **同一 tick 的触发顺序不确定**：槽是 `vector`，但降级会把高层的条目追加到后面，所以"先创建的先触发"不成立。现在同一 tick 到期的定时器按创建顺序触发（`TestSameTickFiresInCreationOrder`）。
- 没有"下一次最早什么时候要醒"的接口，主循环只能定时空转：现在有 `NextDeadlineMs`（下界）。
- 每个定时器 `make_unique<Entry>` + `std::function` + `vector::push_back` 三次堆分配，加一次 `FlatHashMap` 插入：现在是 slab 节点，回调放在节点里，稳态下零分配。

### 3.2 设计

- **4 层 × 256 槽**，第 L 层每个槽覆盖 256^L 个 tick。条目按距离当前 tick 的远近放进某一层，槽号取到期 tick 的第 L 个字节。逢 256^L 的整数倍 tick，把第 L 层当前这一格"降级"：条目按剩余时间重新排进更低层。（降级与放置的正确性：到期 tick 与当前 tick 在该层只差 1..256 格，所以一个槽里的条目第一次轮到它时恰好是它该降级的时候，不会提早一圈或晚一圈。）
- **节点在 slab 里，地址稳定**：`std::vector<std::unique_ptr<Node[]>>`，每块 1024 个，扩容只追加一块，不搬动已有节点——回调在执行期间 `AddTimer` 触发扩容，正在执行的那个 `move_only_function` 不会被挪走。空闲节点串成空闲链。
- **侵入式双向链表**：每个槽一条链，节点记着自己在哪个槽（`bucket`），`Cancel` / `Reset` 是 O(1) 摘链，不需要查表。
- **句柄带代数**：`TimerId = (代数 << 32) | (下标 + 1)`。节点释放时代数加一，旧句柄对已经复用的节点不起作用（`TestStaleHandleDoesNotHitReusedSlot`）。
- **同一 tick 的顺序**：到点时把那个槽整个摘下来，按创建序号排序后逐个触发；回调里对"同一 tick 还没轮到的"定时器 `Cancel` / `Reset`，靠 `(下标, 代数, 状态)` 识别，不用碰链表（`TestCallbackCancelsAndResetsOthersInTheSameTick`）。
- **超出四层的延迟**（> 2^32 个 tick，tick = 1ms 约 49 天）：放进最高层"最晚才会轮到"的槽，降级时发现还没到期会再排一次，每约 49 天一跳；延迟最多钳到 2^60 个 tick；当前 tick 封顶在 2^61，`now` 再离谱也不会让 tick 运算溢出（`TestHugeNowDoesNotOverflow`、`TestAbsurdDelaysAreClamped`）。每次降级的代价与"跳了几个 49 天"成正比，所以不要真的把时间拨到 2^60 个 tick 之后再看它跑（我写测试时就这么做过：80 秒）。
- **延迟的起点**：相对"当前时刻"，即最近一次 `Advance` 推进到的 tick（回调里是正在处理的那个 tick，所以回调里 `AddTimer(50)` 在补触发时也保持相位；`TestCallbackAddsTimersRelativeToProcessedTick`）。两次 `Advance` 之间新加的定时器，计时起点是上一次 `Advance`——每帧一次 `Advance` 的循环里这就是"帧时间"。
- **`NextDeadlineMs`** 是下界：不会晚于真正的下一次触发，但上层轮里的定时器会先在更早的时刻被降级一次，所以主循环可能多醒一次、什么也没触发，再算一遍即可。有定时器却没有基准（还没调过 `Advance`）时返回 `nullopt`。

### 3.3 验证：与参考实现逐步对照

`timer_wheel_model_test` 里有一个参考实现：所有定时器放进 `std::map`，按 `(到期 tick, 创建序号)` 排序，推进时从最小的开始弹出——没有层级、没有降级、没有位图。
对随机的操作序列（添加 / 重复 / 取消 / 重置 / 推进，tick 精度 1、7、10，延迟横跨四层轮并超出整个轮，推进步长从 0 到 60 亿毫秒，时间回退，回调里再添加 / 取消 / 重置 / 取消自己 / 重置自己）两边在每一步必须一致：触发的 `(标签, tick)` 序列、返回值、`size()`、`IsActive()`；另外 `NextDeadlineMs` 必须是下界，推进到它的前一毫秒不会有任何触发。
默认每种精度 40 个种子 × 400 步（debug 下几秒）；用环境变量 `BREEZE_TIMER_MODEL_SEEDS` 放大过：1500（debug）与 6000（release，三种精度共约 720 万步）各跑一遍，全部一致。

## 4. 没搬的东西

| 东西 | 原因 |
|---|---|
| wind-server `Time.h` 的全局函数（`NowSec()`、`GetLogicalDay()` 等） | 与 game-server 的 `Now` / `TimeUtil` 是同一件事的两代；合并成 `Now`（帧缓存、模拟）+ `TimeUtil`（纯函数） |
| `TimeUtil::DaysBetween` 的符号 | 保留了绝对值的 `DaysBetween`，另加有符号的 `DayDiff`（wind-server 的 `GetDayDiff` 是有符号的） |
| 把 `TimerWheel` 接进 App | **没做**：`framework/app` 的 `ITickable::Tick(now)` 可以直接 `wheel.Advance(ms)`，主循环 `wait_until` 的截止时间可以取 `min(下一次 tick, NextDeadlineMs)`；这是装配，不是这个库的事，留给用得上的模块 |

## 5. 验证

- `time_util_test` / `now_test` / `timer_wheel_test` / `timer_wheel_model_test`，debug、release、asan+ubsan 都过（asan 下 `timer_wheel_model_test` 约 16 秒）。
- 变异验证（在 `/tmp` 里的隔离副本上逐个改坏关键判断，要求至少一个测试失败）：time 35 个、timer 约 35 个。
  - `FloorDiv` 等 `constexpr` 的变异在编译期被 `static_assert` 杀死（构建失败也算杀死）。
  - `now_test` 一开始没杀死 `FreezeMs(INT64_MIN)` 的哨兵处理——真的测试缺口，补了用例。
  - **没被杀死、已逐个确认是行为等价的**（只影响效率或是不可达的防御）：把各层的放置阈值（`diff < 2^16 / 2^24 / 2^32`）调大（只会让条目多"降级"几次，到期时刻不变）；最高层"最晚才轮到的槽"换成别的槽（同理，多几跳）；`diff == 0` 时的槽号（`expire == cur` 时两个表达式相等）；降级的先后顺序（降下来的条目绝不会落进同一 tick 还要处理的槽，各层互不依赖）。
  - `Advance` 开头 `now_ms < base_ms_` 的提前返回：在加溢出保护之前去掉它是等价的（`target` 为非正数什么也不做），加了饱和减法之后就不等价了——远古时刻会被当成遥远的未来、一口气触发所有定时器，被 `TestTimeGoingBackwardsIsIgnored` 里的 `Advance(INT64_MIN)` 杀死。
- **没验证的**：tsan（见文首）。`Now` 的并发用例只证明"没读到撕裂的字符串"。
