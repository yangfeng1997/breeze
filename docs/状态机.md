# 状态机：`base/fsm`

`fsm::Machine<Ctx, Event, States...>`：编译期的有限状态机。状态是一个个普通结构体，事件是一个 `std::variant`，转移写在状态的 `OnEnter` / `OnExit` / `OnEvent` 里。
只有头文件（`breeze_fsm`，INTERFACE），只依赖标准库（用 `cxxabi.h` 给状态名 demangle），不限平台。

本文记录**为什么是这个样子**：前身是 silver-server 的通用引擎 `src/utils/fsm/Fsm.h`（238 行），移植时重写了语义。API 与语义的细节在 `fsm.h` 开头的注释里（带一个完整的例子），本文不重复。

**状态**：debug / release / asan+ubsan 下通过；对关键判断逐个改坏做过变异验证（§4）。状态机本身是单线程的，没有并发要验证，tsan 不适用。

> 说明：你给的 `component/framework/fsm` 目录里只有 `ModuleFsm` / `PlatformFsm`，那是 silver 自己的**模块启动流程**（握手 → 加载数据 → 注册 → 同步 → 构建 → 对外服务），
> 绑在它的 `Module` / `Platform` / `Logger` / `RpcMsgMgr` 上，没有搬；breeze 的 `framework/app` 已经有按依赖排序的启动流程。它们用到的**通用引擎**在 `utils/fsm/Fsm.h`，搬的是这个。

## 1. 在原代码里发现并处理的问题

- **`Transition` 在状态自己的回调执行期间把它销毁**：`Machine::Transition` 里 `m_state.emplace<NextState>()` 直接销毁当前状态，而它通常是在当前状态的 `OnEvent`（或 `OnEnter`）里被调用的——回调返回之前再碰任何成员都是未定义行为。现在**转移是延迟的**：回调里请求转移只是登记，回调返回之后机器才依次 `OnExit` → 切换 → `OnEnter`（`fsm_test` `TestTransitionIsDeferred`：登记转移之后继续读写一个超出 SSO 的字符串成员，asan 下不报）。
- **注释写"入队、可重入"，其实没有队列**：事件直接递归分发，回调里发事件会在转移进行到一半时重入。现在真的有队列：回调里调 `OnEvent(e)` 只是排队，等当前回调与它引起的转移都做完，按先进先出处理，新事件看到的是转移之后的状态（run-to-completion，与 UML 状态机一致，`TestChainedTransitionsAndQueuedEvents`）。
- **每个状态必须同时定义 `OnEnter` 与 `OnExit`**：`Machine` 直接调 `st.OnEnter(...)` / `st.OnExit(...)`，缺哪个都编译不过；而文件里写好的探测辅助（`has_on_enter` 等）根本没被用到。现在三个成员都是可选的（用 concept 探测），`int` 或 `void` 返回都行（`TestCallOrderAndOptionalMembers`）。
- **辅助函数 `call_on_exit` 在"有 `OnExit`"的分支里没有 `return`**：流出非 void 函数末尾是未定义行为。它没被用到，是死代码，但谁照着抄就中招。已删除。
- **`FSM_UNHANDLED = -1` 与普通错误码混在一起**：业务回调返回 `-1` 表示失败，调用方分不清是"没人处理"还是"处理失败"。现在是 `fsm::kUnhandled`（`int` 的最小值），错误码用你自己的；另有 `kNotStarted`、`kAlreadyStarted`、`kTooManySteps`。
- **构造函数里调用初始状态的 `OnEnter`，返回值被丢掉**：那时外层对象往往还没构造完（旧用法是 `Module` 的构造函数里初始化状态机，`OnEnter` 又去调 `Module`）。现在构造函数不调用任何回调，要显式 `Start()`，进入失败的错误码从 `Start` 返回（`TestStartReportsEnterFailure`）；`Start` 之前分发事件返回 `kNotStarted`。
- **错误处理没有定义**：`OnEnter` 失败时状态已经换了、`OnExit` 失败时没换，但都没写。现在明确：**`OnExit` 返回非 0 = 否决这次转移，留在原状态；`OnEnter` 返回非 0 = 新状态已经进入（回滚没有意义），错误码交给调用方；出错就停，排队的事件和待执行的转移全部丢弃**（`TestVetoAndEnterFailure`）。
- **状态名靠解析 `__PRETTY_FUNCTION__`**：取 `"T = "` 之后到第一个 `]` 或 `>` 之前，状态类型带模板参数（`Foo<int>`）就在 `>` 处被截断。现在用 `typeid` + `abi::__cxa_demangle`。
- 状态之间可以无限互相转移（A 一进入就转 B、B 一进入就转 A）：一次分发里转移 + 处理的排队事件总数超过 256 返回 `kTooManySteps`，状态机停在某个一致的状态上（`TestInfiniteTransitionLoopIsCut`、`TestEventSelfQueueLoopIsCut`）。
- 回调抛异常：旧版没有任何保护。现在"正在分发"标记复位，排队的事件与登记的转移丢弃，状态机仍然可用（`TestHandlerThrows`）。

## 2. 设计

- **事件是封闭的 `std::variant`**：分发是 `std::visit(状态, 事件)`，没有处理者的组合编译出"返回 `kUnhandled`"，没有虚函数、没有堆分配（除了事件队列）。
- **状态类型要可移动构造**：待执行的转移先把新状态构造出来（带参数 `Transition<S>(args...)`），回调返回之后再按下标原地构造进去，所以只要求可移动构造，不要求可移动赋值（`std::variant` 的移动赋值才要求），状态里可以有 `unique_ptr`、`const` 成员，也可以没有默认构造函数（`TestStartVariants`）。
- **转移与事件的先后**：先做登记的转移，再处理排队的事件。同一个回调里请求了多次转移，以最后一次为准。转移到当前状态是完整的一次转移（`OnExit`、重新构造状态对象、`OnEnter`，`TestSelfTransitionAndTransitionArguments`）。
- **返回值**：第一个非 0 的错误码；最外层事件当前状态没有处理者返回 `kUnhandled`，排队的事件没人处理则默默忽略。
- **用法上的一个限制**：状态的成员函数要定义在**所有状态都定义完之后**（同一个头文件的下半部分或 .cpp）：函数体里调用 `m.Transition<B>()` 需要状态机类型完整，而状态机又要求它的全部状态类型完整。旧版的 `ModuleFsm.h` / `ModuleFsm.cpp` 就是这样分开写的；`fsm.h` 开头的例子也是这样。

## 3. 没做的

- **分层状态机 / 历史状态 / 守卫表达式**：守卫写在 `OnEvent` 里（条件满足才 `Transition`）就够了；需要分层时用两个状态机嵌套（一个状态里持有另一个 `Machine`）。
- **定时转移**：状态里要超时就用 `TimerWheel`，到点向状态机发一个超时事件。
- **线程安全**：只在一个线程里用；跨线程要自己投递到那个线程再 `OnEvent`。

## 4. 验证

- `fsm_test`：文件头的例子、调用顺序与可选成员（`void` / `int` 返回）、转移延迟、`OnEnter` 里的转移链、事件排队与先进先出、`OnExit` 否决、`OnEnter` 失败、事件回调返回错误（自己返回的、排队的事件返回的）、两种循环保护、自转移与带参数的转移、`Start` 的各种情形（无默认构造的状态、从非第一个状态开始、重复 `Start`、`Start` 之前分发）、不可拷贝、回调抛异常。
- **随机操作下的不变量**：4 个状态、3 种事件，每个回调按随机数决定转移 / 排队事件 / 返回错误 / 返回 `kUnhandled` / 登记两次转移，`OnEnter` 随机失败，`OnExit` 随机否决；每次操作后检查：不在分发中、队列为空、"已进入未离开"的状态恰好一个、当前状态就是最近进入的那个；每个状态对象带一个魔数、析构时清零，回调里检查魔数——回调只会在活着的状态对象上被调用（40 个种子 × 4000 次操作，三种结局都出现过）。
- **变异验证**（`/tmp` 里的隔离副本上逐个改坏关键判断，要求至少一个测试失败）：19 个变异全部被杀死，覆盖：排队判断、转移登记、出错清理（`Abort` 的两半）、否决与进入失败、两处步数上限（去掉后是死循环，靠测试超时杀死）、`Start` / 事件的状态检查、异常复位、返回值透传。
  - 第一轮有 3 个没被杀死：
    - **真的测试缺口**：事件回调自己返回错误时，它排的事件与登记的转移没有被丢弃——删掉那一处 `Abort()` 测试照样过；排队的事件返回错误被忽略也一样。补了 `TestEventHandlerErrors`（错误码原样返回、状态不变、队列为空、之后的事件不会撞上残留的转移）。
    - 另一个是我写的变异本身有问题：加在 `return` 之后的赋值是死代码，改成去掉 `Transition` 里"回调中只登记"的判断后被杀死。
- **没验证的**：tsan 不适用（单线程）；GCC（本机只有 clang）。
