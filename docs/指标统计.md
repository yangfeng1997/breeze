# 指标统计：`base/metrics`

目前只有 `MessageStats`：按消息 id / 名字统计条数与字节数，周期性写日志。用来找"哪种消息最话痨"。
`breeze_metrics` 依赖 `breeze_container`（头文件里用 `FlatHashMap`）与 `breeze_logger`（只在 `.cpp` 里，PRIVATE）。

本文记录**为什么是这个样子**：前身是 fir 的 `CmdAnalysis`（`CmdAnalysis.{h,cpp}`）。API 的细节与约束写在头文件注释里，本文不重复。

**状态**：debug / release / asan+ubsan 下 `message_stats_test` 通过，对关键判断逐个改坏做过变异验证（§4）。
**非线程安全是设计，不是遗漏**：一个实例只给一个线程用，所以没有并发要验证，tsan 在这里没有意义。

---

## 1. 来源与取舍

| 东西 | 取舍 |
|---|---|
| `CmdAnalysis` | **改名 `MessageStats`**：`cmd` / `para` 是老协议里两个字节的术语，breeze 没有这个概念。数据结构、"开关 + 周期上报 + 上报后清零"的用法保留，其余重写（§2） |
| `CmdAnalysis` 的按 `(cmd, para)` 与按名字两套统计 | **保留两套**（按 `uint32` id、按名字），报告里分开列；id 不再拆成两列 |
| 旧版的 `Timer` / `zRTime` / `Fir::logger` / `zMutex` | 全部不依赖：时间由调用方传入、日志走 `LOG_INFO`、不加锁 |

## 2. 在原代码里发现并处理的问题

- **累加和上报搅在一起**：`add(..., addlog)` 在**持锁的热路径里**检查定时器，到点就同步写日志并清零。一次慢的日志写入会拖住所有正在 `add` 的线程。现在 `Add` 永远不写日志，上报由调用方周期性调 `Tick`；`Tick` 先把报告拼好、**清零之后**才调 sink，sink 里再 `Add` 的数据不会被冲掉（`message_stats_test` `TestTickWindow` 末尾）。
- **每次 `add` 查两次 `std::map`**（`cmdList[k].num++; cmdList[k].size += size;`），按名字统计时每次还用 `const char*` 构造一个临时 `std::string`（堆分配）。现在一次查找；名字用异构查找（`FlatHashMap<std::string, …, NameHash, std::equal_to<>>` 用 `string_view` 查），命中时零分配。
- **键的数量没有上限**：名字来自消息，对端能构造出任意多个，内存跟着涨。现在每套键最多记 `max_keys`（默认 4096）个，之后的新键合计进 `dropped`，已记下的键照常累加（`TestMaxKeys`：总量守恒——各项之和加 `dropped` 恰好等于发出的总数）。
- **一次全量打印**：键多的时候一条 Tick 刷出几千行日志。现在 Tick 的报告每套键只列前 `report_top_n`（默认 50）项，其余折成 `... N more`。
- **开关与数据的线程安全是假的**：`_switch` 在锁外读写，`off()` 清数据时也没拿锁——`on()` / `off()` 与 `add()` 并发就是数据竞争。现在**明确非线程安全**，一线程一实例；要汇总多线程就在上层各自取 `GetSnapshot()` 再合并。
- **没数据也照打标题**：现在没数据的窗口不上报。
- **时间用墙钟**：旧版的 `Timer` 取 `zRTime`。GM 拨时间会让上报提前或迟迟不出。现在 `Tick(now_ms)` 由调用方传入，约定传 `Now::SteadyMs()`。

## 3. 设计要点

- **窗口从第一次 `Tick` 起算**（`Enable` 之后、或上一次上报之后），所以窗口长度是近似的，误差不超过两次 `Tick` 的间隔；报告里的 `window=…ms` 是实际过去的时间，不是配置的 `interval_ms`（`TestTickWindow`：隔了 12 秒才 `Tick`，报告写 12000）。
- **没数据的窗口也算过去了**：下一窗口从这一刻起算。否则"空了一整天"之后第一条消息会立刻触发上报。
- **`interval_ms <= 0` = 每次 `Tick` 都上报**（有数据时）；时钟回退时也照报（`TestTickEdgeCases`）。
- **`Disable` 清数据并让窗口重新起算**；`Reset` 只清数据，不改开关、不动窗口。重新 `Enable` 是从零开始。
- **排序**：count 降序，再 bytes 降序，再键升序，同样的数据永远同样的顺序，日志可以直接 diff。
- **默认关闭**：关着的时候 `Add` 只是一次分支。预期用法是 GM / 运维命令临时打开。

## 4. 验证

- `message_stats_test`：默认关闭与幂等的 `Enable`、id 与名字各自累加（含空名字、带 `'\0'` 的名字、字面量 `0` 选 id 重载）、排序三级键、`Disable` / `Reset` 语义、`max_keys`（含 0 名额，总量守恒）、报告的**逐字比对**（含 `top_n` 折叠、`window=0ms`、`dropped` 行）、`Tick` 的各种时序、默认写日志（读回 stderr，确认级别是 `[info]`），以及与 `std::map` 参考实现的随机对照（300 轮 × 400 步，含 `Reset` / `Disable` / `Enable` 与 `max_keys` 封顶）。debug、release、asan+ubsan 都过。
- 变异验证（在 `/tmp` 的隔离副本上逐个改坏关键判断，要求至少一个测试失败）：50 个，杀死 49 个。
  - **没被杀死的 1 个、确认是行为等价**：把 `NameHash` 换成恒返回 0。容器照样正确，只是所有名字落进同一条探测序列、退化成线性查找——只影响性能，测试看不出来。
  - 第一轮有两处没被杀死，都是真问题，已处理：①`Tick` 里 `interval_ms > 0 &&` 这个子句，测试里没有"时钟回退"的用例，补了（`interval_ms <= 0` 时回退也照报）；②"只有名字、没有 id"的数据会不会触发上报没有用例，补了（`OnlyName`）。另有一处是代码多余：`top_n == 0 || top_n > size` 里的 `>` 与 `>=` 等价，改写成 `top_n == 0 ? size : min(top_n, size)`，不再有这个多余的比较。
  - 同时补了"重复 `Enable` 是幂等的"（变异成"取反"原先没被发现）。
