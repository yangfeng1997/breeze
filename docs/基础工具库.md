# 基础工具库：`base/assert` `base/backtrace` `base/defer` `base/singleton` `base/noncopyable` `base/string` `base/random` `base/hash` `base/vartype` `base/time_record` `base/uri`

十一个小库，都是游戏服务进程里到处会用到、与网络和线程无关的东西：防御式断言、调用栈、`DEFER`、单例、不可拷贝基类、字符串工具、伪随机数、稳定的字节哈希、弱类型值、耗时记录、URI 解析。每个一个目录、一个 CMake 目标。
时间与定时器见 [时间与定时器.md](时间与定时器.md)，哈希容器见 [基础容器库.md](基础容器库.md)，状态机见 [状态机.md](状态机.md)，事件总线见 [事件总线.md](事件总线.md)。

本文记录**为什么是这个样子**：这些代码在 `cpp-game-server-cpp`、`cpp-game-server-main`、`cpp-wind-server`、`cpp-wind-server_back-cpp`、
`cpp-wind-server-master` 里各有几代前身，合并时做了哪些取舍、修了哪些 bug、哪些没搬。API 的细节与约束写在头文件注释里，本文不重复。

**状态**：debug / release / asan+ubsan 下全部测试通过；对关键判断逐个改坏做过变异验证（见各节，未被杀死的变异都已逐个确认是行为等价的，写在 §6）。
**tsan 没有在本机跑过**（环境原因，见 `网络库设计.md` §11.2）。这四个库里并发相关的只有：`ASSERT` 的按调用点计数（一个原子 `fetch_add`）、`Singleton` 的首次构造（靠函数内 static）、
`ThreadRandom` 的线程局部状态（无共享）。逻辑简单，但上真机前仍不要当作已验证。

## 3. `base/assert` 与 `base/backtrace`

### `ASSERT*` 的行为

- Debug（未定义 `NDEBUG`）：失败 → 经默认 logger 写 Fatal（表达式、位置、调用栈），排空日志队列后 abort。
- Release：失败 → 执行防御式控制流（return / continue / break），**服务不宕机**；记一条 Error 日志，但**每个调用点只在第 1、2、4、8…次失败时记**（`assert_test` `TestThrottlePerSite`：1000 次失败只出 10 条）。
- `BREEZE_ASSERT_FATAL=0/1` 可以不看 `NDEBUG` 强制选择模式。`assert_test`（模式 0）与 `assert_fatal_test`（模式 1）各编成一个可执行文件，两条路径都有测试。

原版的问题：Release 下每次失败都往 stderr 打一行。一个热路径上的 bug（每帧每个玩家失败一次）会把磁盘写满；而且 stderr 在线上通常没人收。现在走默认 logger（线上是文件），并按调用点指数退避。

文件叫 `assert_macros.h` 而不是 `assert.h`：`base/assert` 在 include 路径里，叫 `assert.h` 会盖掉系统的 `<assert.h>`，`<cassert>` 就坏了。

### `Backtrace`（`base/backtrace`）

- 原版把 `backtrace_symbols` 的输出当字符串解析（找最后一个 `(` 与 `+`），路径里带 `(` 或 `+` 就会错位；每次要 `malloc` 一个字符串数组。改用 `dladdr` 直接拿符号名与偏移。
- 输出每帧一行：`#0 0x… 符号+偏移 (模块+模块内偏移)`。后面括号里的东西让**被剥离符号的发布包**也能离线还原：`addr2line -f -C -e <模块> <偏移>`。
- 符号名只认动态符号表：可执行文件要 `-rdynamic`（CMake：`ENABLE_EXPORTS ON`）。测试目标都设了；服务进程要自己设。
- 不用 glibc 的 `backtrace()`：ASan 会拦截它，栈顶多出一层拦截器帧，`skip` 的帧数就不准了（`assert_fatal_test` 在 asan 下用 `top frame == 宏所在函数` 查出过这个）。改用 libgcc 的 `_Unwind_Backtrace`，没有这个问题。
- 返回地址落在下一个函数里（调用点是上一个函数的最后一条指令，常见于 noreturn 调用）时，符号查找用 `pc - 1`（`backtrace_test` `TestReturnAddressAtFunctionEntry`）。
- 独立目录之后：`breeze_assert` 以 PRIVATE 方式依赖 `breeze_backtrace`（断言失败时用它留调用栈），`Backtrace` 本身不依赖日志与断言。`backtrace_test` 自带 `CHECK`，不再借用断言的测试工具。
- **不是 async-signal-safe**（`malloc`、`dladdr` 内部加锁）：别在信号处理函数里调。

## 4. `base/defer`、`base/singleton`、`base/noncopyable` 与 `base/string`

### `Defer`

- `DEFER(...)` 的变量名用 `__COUNTER__`，原版用 `__LINE__`：同一行出现两个（例如另一个宏展开出两个）就重名（`defer_test` `TestTwoOnOneLine`）。
- 回调直接存在守卫对象里（`sizeof(g) <= 2 个指针`），没有 `std::function` 的类型擦除与堆分配，也支持只能移动的回调（`TestMoveOnlyCallable`）。
- 回调不许抛：在析构里调用，抛出去就是 `std::terminate`。

### `Singleton`

- game-server 那一代是**非原子的双检锁**（数据竞争），而且 `ThreadLocalSingleton` 用裸 `new` 却从不 `delete`，注释却写"线程退出时析构"。master 的函数内 `static T inst` / `thread_local T inst` 由标准保证首次构造线程安全、退出时按构造逆序析构，没有 `new`。
- `singleton_test`：16 个线程并发首次访问，构造函数恰好跑一次（构造里故意 sleep 20ms 让它们重叠）；子进程里 `exit(0)` 后析构函数确实跑了；线程局部的各线程一份、线程退出时析构。
- 静态析构顺序的注意事项写在头文件里：单例之间互相依赖时，被依赖的要先构造。

### `NonCopyable`

- 起初我把它算进"没搬"（两行 `= delete` 就够了），但旧代码里到处是 `: private NonCopyable` 的写法，基类把"这个类不可拷贝"写成一个名字，值得留。现在是 `= delete` 的公开拷贝构造 / 赋值 + protected 的默认构造与析构（非虚）：不能单独实例化，也不能通过基类指针删除派生对象。
- 派生类**既不可拷贝也不可移动**（基类的拷贝被删除，派生类隐式的移动因此也不可用）；空基类优化，继承它不增加大小。要"可移动、不可拷贝"的类型（持有文件描述符的句柄）不要继承它，自己删拷贝、写移动。
- `noncopyable_test` 全是编译期断言（`is_copy_constructible` / `is_move_constructible` / `sizeof` / 基类不能单独构造或销毁）；把基类的拷贝改回 `= default`、把构造改成 public、给析构加 `virtual` 这几个变异都会让它编译失败。

### `str::*`

- 返回 `string_view` 的函数（`Split` / `SplitAny` / `Trim*`）传入**临时 `std::string` 会编译失败**（`TemporaryString` concept 的 `= delete` 重载），因为结果会悬空；要拥有就用 `SplitOwned`。注意不能直接写 `std::string&&` 重载：字面量既能转 `string_view` 又能转临时 `std::string`，会有二义性（`string_util_test` 的 `static_assert` 同时检查了"临时串被拒绝、字面量 / 左值 / `string_view` 仍可用"）。
- 大小写转换只认 ASCII，不用 `std::toupper`：后者受 `setlocale` 影响（土耳其语 locale 下 `'i'` 的大写不是 `'I'`），而且 `char` 为负时传给它是未定义行为。256 个字节值逐个对照过（`TestCase`）。
- 数字解析（`ParseNumber<T>`）是**严格**的：整串必须恰好是一个数，不跳空白、不认前导 `+`（同 `std::from_chars`）、溢出失败、浮点的 inf / nan 一律失败，失败返回 `nullopt`。原版的 `ToInt64` / `ToDouble` 会先 `Trim`、失败回默认值，`ToDouble` 还是 `std::stod` + `catch(...)`（库内不抛的约定下不能保留）。要宽松先 `Trim`，要默认值用 `ToNumber<T>(s, def)`。
- `FormatWithCommas`：原版 `std::abs(int64_t)` 对最小值溢出；现在用无符号取绝对值（`TestFormatWithCommas` 含 `INT64_MIN`）。
- `Split` 的语义：`""` 分割得到一个空段；`Join(Split(s, c), c) == s` 恒成立（`TestSplitRandomized` 对 2 万个随机串验证并与朴素实现逐段对照）。
- `Replace`：从左到右、不重叠、结果不再被扫描（`to` 里含 `from` 不会死循环）；与朴素实现随机对照 2 万次。

## 5. `base/random`

- 算法（xoshiro256** + splitmix64 播种 + Lemire 无偏有界采样）原样保留。已知答案由独立的 Python 实现算出（状态 `{1,2,3,4}` 的前几个输出与 xoshiro 作者公布的测试向量一致；Lemire 采样选了会触发"拒绝重抽"分支的 `n`，40 个结果里有 13 次重抽，逐个相同）。
- **可复现的 `Random` 对象**：原版只有线程局部的全局生成器，战斗回放、按种子生成地图、测试都做不到可复现（受线程调度影响）。现在 `Random(seed)` 同一个种子、同样的调用顺序，在任何机器上同样的结果；`State()` / 构造函数可以存取状态。
- 结果已定的调用（`Chance(0)`、`Chance(1)`、分母为 0、`min >= max` 的区间、空权重）**不消耗随机数**：加一个 0% 的事件不会让后面所有结果错位（`TestCertainChancesConsumeNothing`）。
- 窄整数类型的区间（`int8_t` 的 `-128..127`）：有符号 `max - min` 提升成 `int` 再相减会算错，全程在对应的无符号类型里做模运算（这是写测试时自己踩到的，`TestRangeIntegers`）。
- 浮点区间 `[min, max)`：`min + u * (max - min)` 在区间极窄或量级悬殊时会舍入成 `max`，闭上界不属于区间，所以会钳到 `nextafter(max, min)`（`TestFloating`）。
- 线程局部生成器：对象是常量初始化的（访问不带 TLS 初始化守卫），首次使用才用 `getrandom` 播种；原版是 `std::random_device`（可能抛异常，个别平台是确定性的）。**fork 之后子进程重新播种**（`pthread_atfork`），否则父子进程吐出一模一样的序列（`TestForkReseeds`）。
- 新增 `Weighted`（按权重挑下标）：游戏的掉落表、抽卡都要。`uint32_t` 权重在 64 位里累加，总和超过 2^32 不会回绕（`TestWeighted`）。
- `RandomElement` / `Element`：空容器返回 `nullptr`，原版抛 `std::invalid_argument`（库内不抛）。
- **不是密码学安全的**：不要拿它生成 token / 密钥 / 会话 id。

## 5.1 `base/hash`：`MurmurHash64A`

用在**要求同一个键在任何进程、任何机器、任何语言里都落到同一个地方**的场合（分片、路由、一致性哈希、持久化的桶号）：`std::hash<std::string>` 的结果依赖标准库的实现与版本，换个编译器或者让 Go 服务也算一遍就对不上了。
哈希容器内部不需要它（`FlatHashMap` 自己有搅拌，也不要求稳定）。

- 算法与参考实现（smhasher 的 `MurmurHash64A`）逐位一致：`murmur_hash_test` 检查 smhasher 的验证值 `0x1F0D3804`，并有一组由独立 Python 实现算出的固定向量（头文件里抄了一份，Go 侧实现时拿去对拍）。
- **原版 `*(const uint64_t*)key` 解引用**：缓冲区没对齐就是未定义行为（ubsan 报），也违反严格别名。现在按字节 `memcpy`，大端平台上再换字节序，结果与平台无关（`TestUnalignedInput`：同样的内容放在缓冲区的各个偏移上，哈希相同；`TestRandomAgainstNaive`：与逐字节拼装的朴素实现随机对照）。
- 长度参数从 `int` 改成 `size_t`（`int` 超过 2G 溢出）。
- **接口上的陷阱**：原版有 `MurmurHash64A(const void*, int len, uint64_t seed)` 和 `MurmurHash64A(const std::string&, uint64_t seed)` 两个重载。我第一版移植成 `(const void*, size_t, uint64_t seed = 0)` 加 `(string_view, uint64_t seed = 0)`，随手写的 `MurmurHash64A("hello", 42)` 因为 `(const void*, size_t)` 的实参更匹配，把 42 当成了长度，从 6 字节的字面量里读 42 字节——被 asan 查出来（`global-buffer-overflow`）。原版同样有这个陷阱。现在：种子是强类型 `MurmurSeed`（整数不能隐式转成它），裸指针 + 长度的版本叫 `MurmurHash64ABytes`、不与 `string_view` 版本重载；`MurmurHash64A("hello", 42)` 与旧写法 `MurmurHash64A(ptr, len)` 都编译不过（`murmur_hash_test` 里用 `static_assert` 守着）。
- 不是密码学哈希：别拿它做签名 / 防篡改的校验和。

## 5.2 `base/vartype`：`VarType`

字符串存放、按需转成数字 / 布尔的"弱类型"值，用在类型到使用时才确定的地方（GM 命令参数、策划表里的条件参数）。**重写**，保留名字与"和数字 / 字符串直接比较"的用法。原版的问题：

- **浮点精度丢失**：用 `std::to_string` 存浮点，只有 6 位小数：`VarType(1e-9)` 变成 `"0.000000"`，`VarType(0.1 + 0.2)` 读回来不是原来的值。现在用 `std::to_chars` 的最短往返（`TestFloatingRoundTripIsExact`：20 万个随机 double 位型、float 位型逐个往返相等）。
- **转换垃圾得 0**：`strtoll` 读到哪算哪、读不到得 0——`VarType("abc") == 0` 为 true、`"12abc"` 转成 12、`"300"` 转 `uint8_t` 被截断成 44。现在转换是严格的（整串必须是一个数、溢出失败），**比较时转换失败就是不相等**（`TestComparisonWithNumbers`）。
- **一大堆隐式转换运算符**：`operator int32_t / uint32_t / float / bool / int64_t / uint64_t / double / const string&` 混在一起，`int` / `long` / `long long` 之间到处二义性。现在转换是 `explicit`（`static_cast<int>(v)`、`As<int>()`、`TryAs<int>()` 返回 `optional`），`if (v)` 仍然可用。
- **转换缓存**：原版用 `mutable` 的联合体缓存最近一次转换。我第一版把它去掉了（对象不可变，多线程读同一个对象安全），后来按业务的实际用法加了回来：业务单线程，`VarType` 当成员存着、反复转同一个类型，每次重新解析是浪费。现在是**单槽**缓存，存最近一次 `TryAs<T>` 的结果，**失败也存**。实测（release、绑核）：

  | | 不缓存 | 缓存命中 |
  |---|---|---|
  | `As<int>` | 6.4 ns | 0.3 ns |
  | `As<int64>` | 10.8 ns | 0.3 ns |
  | `As<double>` | 11.2 ns | 0.6 ns |
  | `As<bool>` | 6.4 ns | 0.8 ns |
  | `As<int>` 转换失败的串 | 8.5 ns | 0.3 ns |
  | 同一个对象交替转 `int` / `double`（两次） | 16 ns | 17.8 ns（单槽颠簸，约慢 10%，结果仍对） |
  | 100 万个对象各读一次 | 6.7 ns/个 | 1.8–1.9 ns/个（受内存带宽限制） |

  代价：`sizeof` 从 32 变成 48；**非线程安全**——`const` 方法也会写缓存，多个线程同时读同一个对象是数据竞争（本机 tsan 跑不了，所以这条只靠约定，没有测试守着），要共享就各拿一份拷贝。做对了的几处：只缓存标量（不像 fir 的 `vartype.h` 把 `vector&` 缓存起来，那样会泄漏、悬空，见下）；标签按"类别 + 宽度 + 符号"区分（`"300"` 转 `int` 成功、转 `uint8_t` 失败，`"-1"` 转 `int` 成功、转 `uint32_t` 失败，不能串；`long` 与 `long long` 共用）；`long double` 超出 8 字节槽，不缓存；移动后源对象的缓存清空（文本被搬走了，缓存不能还报着旧值）；`==`、hash、format 只看文本，不受缓存影响。`TestCacheFillHitAndFailure` / `TestCacheNeverServesWrongType` / `TestCacheFollowsCopyMoveAssign` / `TestCacheDoesNotAffectComparison`。
  - 顺带调研过 `fir/vartype.h`（和 silver 的 `VarType` 同一个思路的老版本：单槽缓存，外加 vector / map 转换）。它的毛病都跑出来过：`time()` 与 `long` 共用缓存槽（先 `(long)v` 再 `v.time()` 得到 2013 而不是时间戳）；`operator<` 对纯数字串按数值比、其余按文本比，`"9"<"10"<"1a"<"9"` 成环，拿它当 `std::map` 的 key 是未定义行为；隐式拷贝赋值把缓存指针逐位拷过去，`b = a` 之后两个对象析构同一个 vector（ASan 报 use-after-free）；`operator bool` 会 delete 已经交出去的 `vector&`，数字转换又直接覆盖 vector 指针造成泄漏；多字节分隔符按字节集合切（`"路·x"` 被切在"路"的中间）、空段被吞、不认识的分隔符被静默忽略。没有可搬的实现；list / map 复合参数是它唯一有设计价值的功能，已按下一条的设计重做（返回值而不是缓存里的引用、分隔符是参数而不是对象状态、整串匹配而不是字节集合）。
- **容器**（新增）：`TryAsVector<T>` / `TryAsMap<K, V>` 把 `"1|2|3"`、`"12=34|45=78"` 拆成 `vector` / `map`，元素是数字、bool 或 `std::string`。
  - **格式的取舍**（按游戏策划表的常见写法）：项之间 `|`、键值之间 `=`，最多两层。不用 `,`（CSV、GM 命令、中文输入法的全角 `，` 都会撞）、空格（GM 命令用它分隔参数）、`-` `+` `.` `e`（负号、正号、小数点、科学计数法：用 `-` 分隔就没法写负数，用 `.` 分隔会把 `1.5` 拆开），所以这些连同数字、空白一律不许当分隔符，违反返回 `nullopt`。三层以上、元素里带任意字符的数据，别用这个格式，用 YAML / protobuf schema / Luban。
  - **分隔符**：默认值是常量 `kVarItemSep` / `kVarKvSep`，整个工程要换约定就用宏 `BREEZE_VARTYPE_ITEM_SEP` / `BREEZE_VARTYPE_KV_SEP` 覆盖；每次调用也可以传，整串匹配（`"::"`、`"=>"`、`"·"` 都行，不像 fir 按字节集合切，`"路·x"` 会被切在"路"的中间）。用常量承载宏而不是到处直接用宏：有类型、能当参数传，默认值不合法（含数字 / `+-.eE` / 空白、为空、两个相同）时 `static_assert` 在编译期失败（用 `-D` 手工验证过，测试里不覆盖，因为测试先取消了这两个宏）。代价是默认参数在调用处展开，**各目标看到的宏值不一致不会报错，只会各转各的**，所以必须设在 `breeze_vartype` 的 INTERFACE 编译定义上。
  - **严格**：任何元素失败整体 `nullopt`，元素规则同 `TryAs`；元素两端空白去掉；元素不能是空串；空项（`"1||3"`、尾部多一个 `|`）默认失败，`skip_empty = true` 才跳过；整串为空或只有空白得空容器；map 每项必须恰好一个键值分隔符（`"12=34=5"` 失败，多字符分隔符重叠出现如 `"a===b"` 配 `"=="` 也失败）、键重复失败（`"1=1|01=2"` 按 `int` 都是 1）。没有转义。
  - **结果是返回值**（自己拥有），不指向对象内部、不进转换缓存；热路径上加载时解析一次、把容器存下来。
  - `TestVectorFormatAndElementRules` / `TestVectorEmptyItems` / `TestVectorSeparators` / `TestMapFormatAndElementRules` / `TestMapStrictness` / `TestMapSeparators` / `TestContainersDoNotTouchCache`，另有 `TestVectorRoundTripRandom`（3000 轮随机 `int64` / `double` 列表写成文本再读回来相等）与 `TestMapRoundTripRandom`（3000 轮随机 `int32` 映射）。
- **构造的隐式转换**：`VarType('a')`、枚举悄悄变成 bool / 整数；`long long` / `unsigned long long` 在 Linux 上二义性（`int64_t` 是 `long`）。现在所有整数宽度、浮点、bool 都能构造，`char` 类 / 枚举 / 其它指针编译失败（`static_assert`）。
- 比较里浮点用绝对误差（`1e-6f` / `1e-12`），数值大了形同精确比较、小了形同全部相等。现在用相对误差（几个 ulp 内）。
- 其它保留：`VarType == VarType` 是文本完全相同（所以 `"1"` 与 `"1.0"` 不相等——要比数值用新增的 `NumericEqual`）；`const char*` 为空得空串。
- 新增：整数类型也接受"恰好是整数的小数写法"（`"5.0"`、`"1e3"`），表格软件会把整数写成 `5.0`；绝对值到 2^53 以上不接受（double 在那之后分不清相邻整数，`"9007199254740993.0"` 会悄悄变成 `…992`——写测试时发现的）。布尔接受 true/false/yes/no/on/off/1/0，其它数字非零为真。支持 `std::format("{}", v)` 与 `std::hash`。

## 5.3 `base/time_record`：`TimeRecord`

单调时钟的秒表，可选地在析构时把耗时写进日志；用来给一段代码计时、或者抓慢操作（慢 SQL、慢 RPC）。

- 原版 `SetName` 只改名字、不打开日志：先默认构造再起名字，什么也不会记。现在起名字就意味着要记；加了 `Cancel()`（这次不值得记）。
- 新增**慢操作阈值**：`TimeRecord t("RunSql", 50ms)` 平时不出声，只在超过阈值时记一条 Warn；不带阈值是总记一条 Info。
- 日志位置记的是**创建 `TimeRecord` 的那一行**（`std::source_location` 作默认参数），不是析构的地方，也不是库里的某一行。
- 放在单独的 `base/time_record`，没并进 `base/time`：它要写日志（`breeze_logger` PRIVATE 依赖），而 `base/time` 刻意不依赖日志。
- 不可拷贝、不可移动（析构时才记录，拷出去会记两次）。

## 5.4 `base/uri`：`Uri`

解析 RFC 3986 的 URI 引用（绝对 URI 和相对引用都收），用在配置里的服务地址、WebSocket / HTTP 地址、回调 URL 这类地方。语法与组件的语义写在 `uri.h` 开头。
**来源**：sylar 的 `uri.rl`（Ragel 语法）。我先装了 ragel，把原版生成出来真跑了一遍，下面这些都是跑出来的，不是读语法猜的：

- **语法合法的 `http://a:/`（空端口）直接抛 `std::logic_error`**，没有 catch 的话进程 terminate——一个远端输入就能打掉进程。
- **path 只在带 authority 时才保存**：`mailto:John.Doe@example.com`、`urn:...`、`tel:...` 和相对引用 `/a/b?x=1` 的 path 全丢了，`dump` 出 `mailto:///`、`:///?x=1` 这种不合法的东西。
- **端口用 `atoi`**：`:99999999999` 悄悄变成 1215752191，`:65536` 照收；`:0` 与"没写端口"分不清。
- **`dump` 不忠实**：空 path 补成 `/`（`http://a.com` → `http://a.com/`），空的 `?`、`#` 被丢，相对引用也强行输出 `scheme://`。
- **scheme 不转小写**：`HTTP://a.com` 的 `getPort()` 是 0 而不是 80，`HTTP://a.com:80/` 的默认端口判断也落空。
- IPv6 的方括号留在 host 里、`createAddress` 做阻塞的 DNS 查询、返回 `shared_ptr`、setter 不校验（可以写出不合法的 URI）。

重写后的取舍：

- **手写解析，不用 Ragel**：构建不依赖代码生成器；解析是线性的、无递归，超长输入（测试里 4 MB）没有问题。先按 `#`、`?` 从后往前切，再判 scheme，再切 authority，最后校验 path，每一步只做一件事。
- **"没有"与"空"分开**：组件用 `optional`，`http://a/?` 的 query 是空串、`http://a/` 是 nullopt；host 为 nullopt 表示没有 authority，`file:///etc/hosts` 的 host 是空串。这样 `ToString` 能忠实还原，不补 `/`，也不丢空的 `?`。
- **语法严格**：字符集、`%XX`、IP 字面量都按 RFC 校验；唯一放宽的是 path / query / fragment 里 >= 0x80 的字节（直接贴进来的中文路径，原版也放行）。查询串里的裸 `[` `]` 被拒绝，要先编码。
- **IPv6 手写校验**：没有 `::` 时恰好 8 组，有 `::` 时两侧合计不超过 7 组，最后一组可以是点分 IPv4。**没有用 `inet_pton`**，所以这个库不依赖平台；测试里再拿 `inet_pton` 对照。
- 端口范围 0..65535，数字每一步都检查是否越界（长串数字不会回绕）；空端口当作没写；前导零接受。
- 只对 scheme 转小写，不做任何别的规范化（不解码、不去 `..`、host 不转小写），因为规范化是有损的，要比较"是不是同一个资源"由调用方自己决定怎么规范化。
- 百分号编解码和 `ParseQuery`（form 编码，`+` 当空格）放在同一个库里：解析出来的组件是原样的，不配一个解码就没法用。`PercentDecode` 严格，`%` 后不是两位十六进制就失败。

## 7. 验证

- `backtrace_test` / `assert_test` / `assert_fatal_test` / `defer_test` / `singleton_test` / `noncopyable_test` / `string_util_test` / `random_util_test` / `murmur_hash_test` / `var_type_test` / `time_record_test` / `uri_test`，debug、release、asan+ubsan 都过。
- 变异验证（在 `/tmp` 里的隔离副本上逐个改坏关键判断，要求至少一个测试失败）：assert + backtrace 12 个、defer + singleton 8 个、noncopyable 4 个、string 24 个、random 27 个、MurmurHash 7 个、TimeRecord 7 个、VarType 88 个（转换规则 16 个、转换缓存 20 个、容器 52 个）、URI 93 个。**没被杀死的都逐个确认过是行为等价或是测试缺口**：
  - `Backtrace` 里 `pc - 1` 一开始没被杀死——那是个真的测试缺口（noreturn 尾调用的符号归属），为此加了 `FormatBacktraceFrame` 并写了 `TestReturnAddressAtFunctionEntry`，现在被杀死。
  - random 的 Lemire 重抽阈值一开始也没被杀死：我挑的 `n = 3·2^62` 太特殊，`x * n` 的低 64 位只有 4 种取值，把阈值改成别的数结果照样相同。改用 `n = ceil(2/3 · 2^64)` 之后被杀死（测试里写了原因）。
  - `Weighted` 的"累减舍入后落到最后一个有权重项"分支，用状态 `{1, 0x4fc71c71c71c71c7, 3, 4}`（第一个输出恰好是 `UINT64_MAX`）加脚本搜出来的一组权重触达（`TestWeighted`）。
  - VarType 的浮点比较：把"相对误差"换成固定的绝对误差 `1e-3` 没被杀死——真的测试缺口，补了"小量分得清、大量里差几个 ulp 仍相等"的断言。
  - VarType 的布尔转换里，"先按整数解析"的分支删掉后结果不变：凡是能按整数解析的串，按 double 解析也成功且零 / 非零一致——是多余的代码，已经删了。
  - VarType 把 `std::to_chars` 换回 `std::to_string` 没被杀死：这台机器是 C++26 + libstdc++ 16，P2587 之后 `std::to_string(double)` 本身就是最短往返，行为等价。保留 `to_chars` 是因为它在任何语言模式、任何标准库上结果都一样（旧模式下 `to_string` 是 6 位小数）。
  - VarType 去掉 `explicit` 的变异是被 `var_type_test` 里的 `static_assert`（"不能隐式转成 int"）挡在编译阶段杀死的。
  - **VarType 容器的 52 个变异全部杀死**，其中 19 个由测试里的 `static_assert` 在编译期挡住（默认分隔符的值、`ValidSeparator` 的每个字符与空串 / 空白、十个数字逐个）。第一轮有 9 个没被杀死，**全是测试缺口**，已补：①map 的项分隔符只测了单字节，把 `Split` 换成按字节集合切的 `SplitAny` 没被发现，补了 `"||"`、`"·"` 作项分隔符的用例；②分隔符里的数字只测了 `1` 和 `9`，删掉 `0`、`2`–`8` 任何一个都没被发现，改成编译期逐个检查十个数字；另外"恰好一个键值分隔符"用 `int` 值测不出来（值 `"34=5"` 本来就不是数字），要用字符串值。写测试时还发现多字符键值分隔符重叠出现（`"a===b"` 配 `"=="`）有歧义，实现改成从 `pos + 1` 起找第二个，一并拒绝。
  - **VarType 转换缓存的 20 个变异全部杀死，没有等价幸存**：其中 6 个（五种标签编号冲突、`long double` 被当成可缓存）被测试里的 `static_assert`（各标签互不相同且非零、`long double` 为 0）在编译阶段挡住。"缓存只是加速、不改变结果"这件事本身看不出来——"命中"和"每次都重新解析"结果完全一样，所以测试靠友元 `VarTypeTestPeer` 往缓存里塞一个和文本对不上的值（`Poison`），证明转换确实原样取出了它，"失败也命中"同理；缓存的标签、`ok` 位、移动后源对象清空、拷贝 / 赋值带着走，也都是读缓存状态断言的。跨类型污染由"任意两个类型先后转换，结果等于全新对象"的 12×12×27 组合守着（含 `"300"`、`"-1"`、`"3000000000"`、`"0.1"` 这类各类型答案不同的串）。
  - **URI 的两份独立对照**（`uri_test`）：①把 RFC 3986 的 ABNF 原文翻成正则（IPv6 的九个分支逐字翻，不是我实现里的"数组数"算法），加附录 B 的切分正则，对 6 万个按结构拼出来、再随机变异的 ASCII 输入逐个比对"接受 / 拒绝"和各组件（约 1.2 万接受、4.8 万拒绝，两侧都有足够样本）；②IPv6 判定与 `inet_pton` 对 60 万个字符串（一半随机字符、一半按组数 / `::` 位置 / IPv4 尾巴生成再破坏一个字符）。两份都零不一致。
  - URI 变异里有两处没被杀死，都确认是行为等价：`find('#')` 换成 `rfind('#')`（`#` 在任何组件里都不合法，两种切法最后都被字符集检查拒绝）；`CheckChars` 里碰到合法 `%XX` 后的 `i += 2`（后两位十六进制数字本身就是合法字符，跳不跳结果一样）。按这个结论把 `i += 2` 删了，把 `IsIPv6` 里单独的"第二个 `::`"检查也删了（它会落在右侧，被空组检查拒绝）。真正的测试缺口有一处：`IsIPvFuture` 里"`v` 后面至少一位十六进制"的检查，原先的反例 `v.x` 被长度不足的前置判断挡住，没走到那里，补了 `v.xyz` 等。
- **没验证的**：tsan（见文首）；`VarType` 的缓存**明确不提供线程安全**（不是没验证，是约定业务单线程，见 `var_type.h` 文件头）；aarch64 / 非 glibc 平台（`Backtrace` 依赖 `dladdr`、`random` 依赖 `getrandom`，没有在别的平台编过）；GCC（本机只有 clang，`fsm` 与 `vartype` 用了 concept 与 `std::format`，别的编译器没试过）。
