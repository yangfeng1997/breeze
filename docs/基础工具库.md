# 基础工具库：`base/assert` `base/util` `base/string` `base/random`

四个小库，都是游戏服务进程里到处会用到、与网络和线程无关的东西：防御式断言与调用栈、`DEFER` 与单例、字符串工具、伪随机数。
时间与定时器见 [时间与定时器.md](时间与定时器.md)，哈希容器见 [基础容器库.md](基础容器库.md)。

本文记录**为什么是这个样子**：这些代码在 `cpp-game-server-cpp`、`cpp-game-server-main`、`cpp-wind-server`、`cpp-wind-server_back-cpp`、
`cpp-wind-server-master` 里各有几代前身，合并时做了哪些取舍、修了哪些 bug、哪些没搬。API 的细节与约束写在头文件注释里，本文不重复。

**状态**：debug / release / asan+ubsan 下全部测试通过；对关键判断逐个改坏做过变异验证（见各节，未被杀死的变异都已逐个确认是行为等价的，写在 §6）。
**tsan 没有在本机跑过**（环境原因，见 `网络库设计.md` §11.2）。这四个库里并发相关的只有：`ASSERT` 的按调用点计数（一个原子 `fetch_add`）、`Singleton` 的首次构造（靠函数内 static）、
`ThreadRandom` 的线程局部状态（无共享）。逻辑简单，但上真机前仍不要当作已验证。

| 组件 | 来源 | 取舍 |

## 3. `base/assert`

### `ASSERT*` 的行为

- Debug（未定义 `NDEBUG`）：失败 → 经默认 logger 写 Fatal（表达式、位置、调用栈），排空日志队列后 abort。
- Release：失败 → 执行防御式控制流（return / continue / break），**服务不宕机**；记一条 Error 日志，但**每个调用点只在第 1、2、4、8…次失败时记**（`assert_test` `TestThrottlePerSite`：1000 次失败只出 10 条）。
- `BREEZE_ASSERT_FATAL=0/1` 可以不看 `NDEBUG` 强制选择模式。`assert_test`（模式 0）与 `assert_fatal_test`（模式 1）各编成一个可执行文件，两条路径都有测试。

原版的问题：Release 下每次失败都往 stderr 打一行。一个热路径上的 bug（每帧每个玩家失败一次）会把磁盘写满；而且 stderr 在线上通常没人收。现在走默认 logger（线上是文件），并按调用点指数退避。

文件叫 `assert_macros.h` 而不是 `assert.h`：`base/assert` 在 include 路径里，叫 `assert.h` 会盖掉系统的 `<assert.h>`，`<cassert>` 就坏了。

### `Backtrace`

- 原版把 `backtrace_symbols` 的输出当字符串解析（找最后一个 `(` 与 `+`），路径里带 `(` 或 `+` 就会错位；每次要 `malloc` 一个字符串数组。改用 `dladdr` 直接拿符号名与偏移。
- 输出每帧一行：`#0 0x… 符号+偏移 (模块+模块内偏移)`。后面括号里的东西让**被剥离符号的发布包**也能离线还原：`addr2line -f -C -e <模块> <偏移>`。
- 符号名只认动态符号表：可执行文件要 `-rdynamic`（CMake：`ENABLE_EXPORTS ON`）。测试目标都设了；服务进程要自己设。
- 不用 glibc 的 `backtrace()`：ASan 会拦截它，栈顶多出一层拦截器帧，`skip` 的帧数就不准了（`assert_fatal_test` 在 asan 下用 `top frame == 宏所在函数` 查出过这个）。改用 libgcc 的 `_Unwind_Backtrace`，没有这个问题。
- 返回地址落在下一个函数里（调用点是上一个函数的最后一条指令，常见于 noreturn 调用）时，符号查找用 `pc - 1`（`backtrace_test` `TestReturnAddressAtFunctionEntry`）。
- **不是 async-signal-safe**（`malloc`、`dladdr` 内部加锁）：别在信号处理函数里调。

## 4. `base/util` 与 `base/string`

### `Defer`

- `DEFER(...)` 的变量名用 `__COUNTER__`，原版用 `__LINE__`：同一行出现两个（例如另一个宏展开出两个）就重名（`defer_test` `TestTwoOnOneLine`）。
- 回调直接存在守卫对象里（`sizeof(g) <= 2 个指针`），没有 `std::function` 的类型擦除与堆分配，也支持只能移动的回调（`TestMoveOnlyCallable`）。
- 回调不许抛：在析构里调用，抛出去就是 `std::terminate`。

### `Singleton`

- game-server 那一代是**非原子的双检锁**（数据竞争），而且 `ThreadLocalSingleton` 用裸 `new` 却从不 `delete`，注释却写"线程退出时析构"。master 的函数内 `static T inst` / `thread_local T inst` 由标准保证首次构造线程安全、退出时按构造逆序析构，没有 `new`。
- `singleton_test`：16 个线程并发首次访问，构造函数恰好跑一次（构造里故意 sleep 20ms 让它们重叠）；子进程里 `exit(0)` 后析构函数确实跑了；线程局部的各线程一份、线程退出时析构。
- 静态析构顺序的注意事项写在头文件里：单例之间互相依赖时，被依赖的要先构造。

### `str::*`

- 返回 `string_view` 的函数（`Split` / `SplitAny` / `Trim*`）传入**临时 `std::string` 会编译失败**（`TemporaryString` concept 的 `= delete` 重载），因为结果会悬空；要拥有就用 `SplitOwned`。注意不能直接写 `std::string&&` 重载：字面量既能转 `string_view` 又能转临时 `std::string`，会有二义性（`string_util_test` 的 `static_assert` 同时检查了"临时串被拒绝、字面量 / 左值 / `string_view` 仍可用"）。
- 大小写转换只认 ASCII，不用 `std::toupper`：后者受 `setlocale` 影响（土耳其语 locale 下 `'i'` 的大写不是 `'I'`），而且 `char` 为负时传给它是未定义行为。256 个字节值逐个对照过（`TestCase`）。
- 数字解析（`ParseNumber<T>`）是**严格**的：整串必须恰好是一个数，不跳空白、不认前导 `+`（同 `std::from_chars`）、溢出失败、浮点的 inf / nan 一律失败，失败返回 `nullopt`。原版的 `ToInt64` / `ToDouble` 会先 `Trim`、失败回默认值，`ToDouble` 还是 `std::stod` + `catch(...)`（库内不抛的约定下不能保留）。要宽松先 `Trim`，要默认值用 `ToNumber<T>(s, def)`。
- `FormatWithCommas`：原版 `std::abs(int64_t)` 对最小值溢出；现在用无符号取绝对值（`TestFormatWithCommas` 含 `INT64_MIN`）。
- `Split` 的语义：`""` 分割得到一个空段；`Join(Split(s, c), c) == s` 恒成立（`TestSplitRandomized` 对 2 万个随机串验证并与朴素实现逐段对照）。
- `Replace`：从左到右、不重叠、结果不再被扫描（`to` 里含 `from` 不会死循环）；与朴素实现随机对照 2 万次。

## 5. `base/random`

- 算法（xoshiro256** + splitmix64 播种 + Lemire 无偏有界采样）原样保留。已知答案由独立的 Python 实现算出（状态 `{1,2,3,4}` 的前几个输出与 xoshiro 作者公布的测试向量一致；Lemire 采样选了会触发"拒绝重抽"分支的 `n`，40 个结果里有 13 次重抽，逐个相同）。
- **可复现的 `Random` 对象**：原版只有线程局部的全局生成器，战斗回放、按种子生成地图、测试都做不到可复现（受线程调度影响）。现在 `Random(seed)` 同一个种子、同样的调用顺序，在任何机器上同样的结果；`State()` / 构造函数可以存取状态。
- 结果已定的调用（`Chance(0)`、`Chance(1)`、分母为 0、`min >= max` 的区间、空权重）**不消耗随机数**：加一个 0% 的事件不会让后面所有结果错位（`TestCertainChancesConsumeNothing`）。
- 窄整数类型的区间（`int8_t` 的 `-128..127`）：有符号 `max - min` 提升成 `int` 再相减会算错，全程在对应的无符号类型里做模运算（这是写测试时自己踩到的，`TestRangeIntegers`）。
- 浮点区间 `[min, max)`：`min + u * (max - min)` 在区间极窄或量级悬殊时会舍入成 `max`，闭上界不属于区间，所以会钳到 `nextafter(max, min)`（`TestFloating`）。
- 线程局部生成器：对象是常量初始化的（访问不带 TLS 初始化守卫），首次使用才用 `getrandom` 播种；原版是 `std::random_device`（可能抛异常，个别平台是确定性的）。**fork 之后子进程重新播种**（`pthread_atfork`），否则父子进程吐出一模一样的序列（`TestForkReseeds`）。
- 新增 `Weighted`（按权重挑下标）：游戏的掉落表、抽卡都要。`uint32_t` 权重在 64 位里累加，总和超过 2^32 不会回绕（`TestWeighted`）。
- `RandomElement` / `Element`：空容器返回 `nullptr`，原版抛 `std::invalid_argument`（库内不抛）。
- **不是密码学安全的**：不要拿它生成 token / 密钥 / 会话 id。

## 6. 没搬的东西与原因

| 东西 | 原因 |
|---|---|
| `noncopyable` | `= delete` 两行就是了 |
| `stringify.h` / `Printable.h`（把容器、pair、tuple 打印成字符串） | `std::format` 已经能直接 `{}` 打印容器、pair、tuple（clang + libstdc++ 下验证过），日志宏本来就是 `std::format` |
| `Version.h`（写死的 `"wind-server" "0.1.0"`） | 项目名与版本号是硬编码的，没有可复用的部分；真要版本号应该由 CMake 的 `project(VERSION)` 与 `git describe` 生成 |

| `Singleton` 的 `SingletonPtr`（back-cpp，`shared_ptr` 单例） | 没有人需要 |
| `Mutex` / `Condition` / `CountDownLatch` | 见 `线程基础库.md` |
| logger、config、args、Module / Application、net、thread、queue、buffer | 本仓库已有 |

## 7. 验证

- `backtrace_test` / `assert_test` / `assert_fatal_test` / `defer_test` / `singleton_test` / `string_util_test` / `random_util_test`，debug、release、asan+ubsan 都过。
- 变异验证（在 `/tmp` 里的隔离副本上逐个改坏关键判断，要求至少一个测试失败）：assert + backtrace 12 个、util 8 个、string 24 个、random 27 个。**没被杀死的都逐个确认过是行为等价的**：
  - `Backtrace` 里 `pc - 1` 一开始没被杀死——那是个真的测试缺口（noreturn 尾调用的符号归属），为此加了 `FormatBacktraceFrame` 并写了 `TestReturnAddressAtFunctionEntry`，现在被杀死。
  - random 的 Lemire 重抽阈值一开始也没被杀死：我挑的 `n = 3·2^62` 太特殊，`x * n` 的低 64 位只有 4 种取值，把阈值改成别的数结果照样相同。改用 `n = ceil(2/3 · 2^64)` 之后被杀死（测试里写了原因）。
  - `Weighted` 的"累减舍入后落到最后一个有权重项"分支，用状态 `{1, 0x4fc71c71c71c71c7, 3, 4}`（第一个输出恰好是 `UINT64_MAX`）加脚本搜出来的一组权重触达（`TestWeighted`）。
- **没验证的**：tsan（见文首）；aarch64 / 非 glibc 平台（`Backtrace` 依赖 `dladdr`、`random` 依赖 `getrandom`，没有在别的平台编过）。
